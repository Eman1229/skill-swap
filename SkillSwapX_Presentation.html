Section 1

Quick Recap: Problem Statement & Objectives

❌ The Problem

  • High Learning Costs: Traditional platforms (Coursera, Udemy) require subscription fees.
  • Passive Learning: One-way videos lack interactive peer practice & feedback.
  • Matchmaking Friction: Hard to find peers with complementary skill needs (e.g. Flutter ↔ UI/UX).

🎯 Key Objectives

  • Zero-Cost Skill Barter: Exchange time and knowledge without money.
  • AI-Driven Matching: Smart recommendations connecting learners based on demand & supply.
  • Real-time Ecosystem: Integrated live chat, presence, notifications, and AI roadmaps.
🗣️ How to explain this slide (Easy Words)
"The problem is that online courses are expensive and passive. Our objective with SkillSwapX is to create a free barter system where users trade skills directly—for example, I teach you Flutter, and you teach me Graphic Design, guided by AI recommendations."
Section 2

Quick Recap: Proposed System

1. Skill Barter Engine

Allows users to post skills they offer and skills they wish to learn with automated swap request management.

2. AI Guidance Suite

Includes AI Career Compass, Learning Roadmap Generator, and Mentor Compass for custom learning paths.

3. Real-Time Hub

Instant chat with typing status, FCM push alerts, session scheduling, and offline local cache.

🗣️ How to explain this slide (Easy Words)
"Our proposed system has 3 pillars: a P2P Skill Barter engine to trade skills, an AI Suite to generate step-by-step career roadmaps, and a Real-time Messaging Hub for instant communication."
Section 3

System Design: Architecture & Workflows

🏛️ 3-Tier Layered Architecture

  • Presentation Layer: Flutter UI Widgets (Material 3, Dark Theme).
  • Service & State Layer: Providers, Repositories (Swap, Chat, Notification), AI Engine.
  • Data & Backend Layer: Firestore Cloud DB, Supabase Storage, Hive Local DB, FCM.

🔄 Core User Workflow

User Flow:

Sign Up ➔ Set Offered/Needed Skills ➔ Get AI Recommendations ➔ Send Swap Request ➔ Accept & Schedule Session ➔ Live Chat & Swap ➔ Rate Experience
🗣️ How to explain this slide (Easy Words)
"We follow a 3-tier architecture. Flutter handles the mobile UI, Provider manages app state, and Firebase/Supabase power backend operations. When a user requests a skill swap, it processes through our repository layer into Firestore in real-time."
Section 4

Implementation Details

💻 Frontend & State Management

  • Flutter SDK 3.x & Dart: Clean component hierarchy for cross-platform efficiency.
  • Provider & Hive: State management paired with Hive for zero-latency local caching.
  • Custom UI Helper: Unified design tokens for dark themes, gradients, and micro-animations.

🔥 Backend & Real-time Synchronization

  • Firebase Firestore: NoSQL cloud database for instant document sync.
  • Realtime Database: High-frequency presence tracking (online/offline status).
  • FCM & Local Notifications: Instant alert triggers for background message delivery.
🗣️ How to explain this slide (Easy Words)
"For implementation, we chose Flutter for smooth native performance on Android and iOS. For backend, we combined Firebase for document sync with Hive local database so the app works seamlessly even offline."

Section 10

Challenges Faced & Solutions

Challenge 1

Network Connection Drops in Chat

Solution: Built Hive local message queue + FCM background sync.

Challenge 2

AI Roadmap Response Latency

Solution: Cached roadmap steps locally & optimized request payloads.

Challenge 3

Complex Swap Lifecycle State

Solution: Designed dedicated `SwapRequestRepository` state machine.

🗣️ How to explain this slide (Easy Words)
"Our main challenge was maintaining chat state during poor internet connectivity. We solved this by using Hive local storage to queue messages offline until connection is restored."
